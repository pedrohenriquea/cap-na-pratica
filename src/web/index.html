Já ouviu falar do teorema CAP?

O CAP diz que, quando a rede parte as cópias do banco, é preciso escolher: continuar disponível (A) ou responder só dado consistente (C). E ele para aí — partição é evento raro. O PACELC, usado neste gráfico, acrescenta a pergunta do dia a dia: sem falha nenhuma (else), o banco prioriza latência (L) ou consistência (C)?

Rigor: o teorema fala de sistemas com várias cópias. Um banco de uma máquina só (PostgreSQL, MySQL) entra aqui por convenção — isolado pela rede, ele simplesmente fica indisponível, que é o comportamento do lado PC.

            Mais de um tipo de dado?

            Se partes do sistema têm requisitos diferentes — o pedido e o catálogo, por exemplo —, decida uma de cada vez: dê um nome a este conjunto, guarde, e responda de novo para o próximo. No fim a ferramenta diz se um banco só atende a todos ou se vale especializar.
